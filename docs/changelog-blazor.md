# Changelog do cliente Blazor — história congelada

> **Este documento não é mantido.** Ele é o histórico de build do cliente Blazor
> (`entrelares-app`), preservado aqui porque é a memória escrita de como o produto chegou
> onde chegou — versão a versão, com o porquê de cada uma. Ele parou na **1.8.15**, a última
> versão promovida antes de o repositório ser esvaziado (ver
> [`arquivamento-app.md`](arquivamento-app.md)).
>
> O app Flutter tem versionamento **próprio e independente** (`0.2.x+NN` em
> `apps/entrelares_app/pubspec.yaml`, onde o `+NN` é o `versionCode` do Android) e não
> continua esta numeração. Nada aqui descreve o produto atual: descreve como ele foi feito.

---

## Versioning

The app follows [Semantic Versioning](https://semver.org). The current version is defined in the project file and the PWA manifest:

| File | Key |
|---|---|
| `Entrelares.csproj` | `<Version>1.8.15</Version>` (current QA build — see the changelog below) |
| `wwwroot/manifest.webmanifest` | `"version": "1.8.15"` |

The two files above are kept in lockstep and the UI reads the version **from the assembly** at runtime (`Helpers/AppVersion.cs`) — never hardcode it in a page. Within a phase, the **patch number bumps on every app-changing delivery merged to `dev`** so the in-app version identifies the exact DEV/QA build (the earlier "patch = backlog item" mnemonic was retired mid-Phase 5). The minor version bumps at release milestones: `1.6.0` at the Phase 5 release (in production) and **`1.7.0` (Aug 2026) marking the paid-launch gate complete** — Phase 6's feature track carried the patch through `1.6.47` and closed roadmap group 1 (all five freemium gates, billing, the PDF wedge); each milestone carries a matching git tag (`v1.4.0`…`v1.7.0`). The authoritative history is the [Changelog](#changelog).

| `1.7.2` | **T-35 — o token de concorrência otimista deixa de ser adivinhável.** Último achado aberto da exploração adversarial T-32 (T32-A1) e pré-requisito do gate de disponibilidade pública.
